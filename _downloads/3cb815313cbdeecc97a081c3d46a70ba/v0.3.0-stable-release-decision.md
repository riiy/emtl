**决策：批准准备 `0.3.0` Stable 候选 PR；尚未批准合并、Tag、GitHub Release 或 PyPI 上传。**

维护者 2026-11-14 明确选择：以已发布 `emtl==0.3.0b2` 为功能基线，不增加新功能、不更新依赖、不等待原建议约十个工作日的 Beta 观察期。此决定仅替代等待观察期的安排，**不豁免**最终 SHA CI、发行包审计、独立 Review 和分别授予的合并/发行授权。

## 修改范围

仅同步 `0.3.0` 版本来源、正式版 classifier、候选测试默认值、CHANGELOG、README、安装和发布文档。保留 `Requires-Python >=3.11,<3.14`、运行时依赖、OCR 模型和选择机制、模块级 API、`TradingClient` 契约、CLI、交易异常和禁网保护；不改生产交易逻辑。

README 的 commits-since 徽章在 Tag 尚未发布前仍指向已公开的 `v0.3.0b2`；正式发布后需另外更新徽章，不提前指向不存在的 Tag。历史 Beta 测试记录与用于发布门禁的 Beta/rc 参数化案例保留历史版本号。

## 风险与跳过观察期的代价

- 六组各 10 次、总计 60/60 的成功记录，只证明指定时间/环境的 Beta 登录链路通过；不保证未来验证码、券商协议变化后依然成功。
- 未进行真实下单、撤单、成交、超时后委托状态、长时间运行、真实券商侧多账户隔离的完整验收。
- 未验证 Windows、Apple Silicon、PyPy 或所有 Linux 发行版/架构。
- Stable classifier 是发行成熟度元数据，**不是生产实盘交易安全认证**。未经充分自检不建议投入真实资金自动化运行。结果未知不得自动重发订单；发生账户混用、重复委托、凭证泄漏等严重问题，停止使用相关功能。
- 没有观察窗口会减少发现低频故障的机会。出现风险报告或阻断缺陷，必须暂停发布或发布后停止推荐版本，按 `SECURITY.md` 和 Hotfix 流程处理。

## Stable 发布门禁与停止条件

1. 候选 PR 仅包含批准的文件；人工核对功能无变化，独立 Reviewer 输出 `PASS`，阻断问题为零。
2. 维护者单独批准合并后，**最终 master 精确 SHA** 的 Build/check/docs、Offline、Package Alpha CI 均为 success，产物和审计证据对应同一 SHA。
3. `.bumpversion.cfg`、Changelog、SCM 版本、wheel/sdist、运行时版本一致为 `0.3.0`。发行包 `twine check --strict`、元数据/文件/模型审计、SHA-256 以及禁网安装 smoke 全部成功。任何一项失败立即停止；不创建 Tag。
4. 维护者再单独明确授权 Tag、GitHub Stable Release 和 PyPI 上传；`pypi` Environment 有有效 required reviewers。不得使用 PR 事件或未授权 Tag 推送上传。
5. 在 Tag `v0.3.0` 指向的精确 `master` SHA 触发手动 `Release distributions`，选择 `channel=stable`、`publish=true`；若 master 提前移动，停止，重新检查，不能借用旧 SHA 的发布证据。
6. 发布后独立核验 PyPI 文件名、SHA-256、provenance、Tag/Release/Commit；在全新环境从 PyPI 安装固定的 `emtl==0.3.0`，只执行无真实券商交易副作用的 smoke，并归档 Run、Artifact 与哈希。
