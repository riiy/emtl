- **模型资源**：`src/emtl/models/tiny_captcha_model.b64`（解码即原始冻结 ZIP，SHA-256 校验不变）；SHA-256 `27dc2423ad452a3a723ba0d3ccc8d57a81bfda0238497baf94ce22926585cf4a`。
- **独立 100 张验收（此前一次性验收记录）**：96/100 整图正确，前导零 10/10；ddddOCR 旧基准 66/100。该证据为用户在 2026-11-13 提供的预测 CSV/JSON，未将独立样本加入训练或本次测试套件。
- **内部来源分层开发集**：216/220（ACCEPTED 196/200；REJECTED 6/6；SKIPPED 14/14）。内部验证不是最终测试集。
- **CPU 运行实测（此前用户 Linux i5 环境）**：Python 3.11 的精简 Pillow P95 55.76ms；Python 3.12 P95 54.01ms；Python 3.13 P95 52.76ms；均低于 1000ms。测试包含 JPEG 解码/预处理和推理，但不包含加载模型与压缩包解压。
- **精简安装体积（此前 Python 3.11 目标机器）**：源码编译 Pillow + 推理文件 + 模型为 5,721,124 字节，低于 20,000,000 字节。若使用官方 Linux Wheel，则在用户机器上为 22,221,039 字节，不满足 20MB；普通用户 Wheel 安装明确不受这一体积门槛约束。
- **本次源码验收**：应验证内置模型 SHA、纯 Pillow/stdlib 推理、四位字符及前导零、两个 API 调用入口、环境变量切换、Python 版本与包构建产物。新增自动测试只使用合成图片与合成 HTTP，不依赖真实账户或网络。

`pip install emtl` 使用 lightweight；若需要旧引擎，仅 Python 3.11 支持 `pip install 'emtl[ddddocr]'` 并设置 `EMTL_OCR_ENGINE=ddddocr`。切换失败禁止自动回退。源码编译 Pillow 的方式只是目标部署优化，不属于普通用户的默认安装流程。

现有 P2 客户端契约中关于默认 ddddOCR 的描述是历史行为；OCR v1 重构仅覆盖默认引擎/异常和验证码字符串契约，不改动现有交易语义及账户隔离。
